# tmon Web 端布局与样式设计 v0.1

> 日期：2026-08-03 ｜ 状态：规划草案（待用户确认后实现）
> 目标：把当前「列表页 / 详情页」两页式结构改为「左侧任务侧边栏 + 右侧详情工作台」的左右分栏单页结构

---

## 1. 现状问题

| 问题 | 说明 |
|---|---|
| 两页跳转割裂 | 列表与详情是独立路由，切换任务需返回列表再点入，无法快速对比/切换 |
| 任务总览弱 | 全宽表格信息密度低，running 状态不突出，无筛选 |
| 无设计语言 | 系统默认字体、无色彩语义体系、无层次，观感简陋 |
| 无空状态引导 | 没有任务时不提示用户如何使用 tmon |

## 2. 总体布局（信息架构）

```
┌────────────────────────────────────────────────────────────────────────┐
│ ║ 侧边栏（任务列表，始终可见）      ║  主区域（任务详情 + 终端工作台）      │
│ ║──────────────────────────────║──────────────────────────────────────│
│ ║ [● tmon]  v0.1  server ●     ║  ┌─ 任务头 ─────────────────────────┐ │
│ ║ ──────────────────────────   ║  │ id 命令全文   统计×4   操作按钮    │ │
│ ║ 筛选: [全部|运行中|结束|...]  ║  └──────────────────────────────────┘ │
│ ║ 搜索: [按命令/id 过滤______]  ║  ┌─ 进度条（有 progress 上报时显示）──┐ │
│ ║ ──────────────────────────   ║  │ ▓▓▓▓▓▓░░░░ 45%  步骤 3/20         │ │
│ ║ ▎7f2a9c3e curl -o big.bin…   ║  └──────────────────────────────────┘ │

│ ║ ▎a6b7c261 node demo.mjs      ║  │ 绿绿绿黄红红□□□(静默高亮)…        │ │
│ ║  ● 成功    26s               ║  └──────────────────────────────────┘ │
│ ║ ▎b3214e30 ping -n 30 …       ║  ┌─ 终端窗口（xterm.js）────────────┐ │

│ ║ ...                          ║  │ ┌──────────────────────────────┐ │ │
│ ║                              ║  │ │  终端输出流…                  │ │ │
│ ║                              ║  │ └──────────────────────────────┘ │ │
│ ║                              ║  └──────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

**核心意图**：监控是一个「持续观察 + 频繁切换」的活动——侧边栏常驻让任务总览与切换零成本；主区域专注单个任务的「详情 + 交互 + 节奏」三重信息，互不干扰。

## 3. 区域意图详解

### 3.1 侧边栏（任务列表）——「全景」

**意图**：回答三个问题——*有哪些任务？哪些在跑？跑了多久？*；并提供最快捷的切换手段。

| 子结构 | 内容 | 设计意图 |
|---|---|---|
| 品牌区 | tmon 标识 + server 连接状态点（绿=连/灰=断） | 常驻身份标识 + 一眼感知系统健康 |
| 筛选行 | 状态 tab：全部 / 运行中 / 已结束 / 异常 + 搜索框（命令或 id 模糊匹配） | 任务会累积，筛选保证列表始终可扫读 |
| 任务项 | 左侧 4px 状态色条；两行信息：`id 命令摘要`（等宽）+ `状态徽章 时长 [微进度条]` | 色条=状态扫读；命令摘要=身份；时长=紧迫感；微进度条=脚本上报时的实时进展 |
| 选中态 | 强调色左边条 + 浅色背景 | 明确当前查看对象 |
| 排序 | running 置顶，其余按开始时间倒序 | 正在进行的永远在最容易看到的位置 |
| 空列表 | 引导文案「让 Agent 用 `tmon "命令"` 执行即可在此查看」+ 示例代码块 | 教育用户，降低使用门槛 |

### 3.2 任务头（详情摘要）——「身份卡」

**意图**：回答——*这是什么任务？状态如何？能做什么操作？*

| 区块 | 内容 | 设计意图 |
|---|---|---|
| 身份区 | 任务 id（等宽）+ 完整命令全文（可点击复制，hover 显示复制提示） | 命令全文是任务的"签名"，随时可精确复制 |
| 统计区 | 四项紧凑键值对：总时长 / 输出行数 / 最近间隔 / 最长静默；超阈值项标橙/红 | 无需滚动即可判断「跑得快不快、有没有卡住」；间隔指标直接回应核心焦虑 |
| 操作区 | Ctrl-C（常规）/ 强制终止（危险红）/ 复制 id；仅 running 显示，操作结果就地反馈（✓已发送 / ✗原因） | 操作在视线焦点内，反馈不跳转不弹窗 |

### 3.3 进度条区（条件渲染）——「脚本视角」

**意图**：脚本通过 `tmon progress/stage` 上报时，把「黑盒长任务」变成「已知阶段的可见进度」。
- 显示当前阶段名 + 百分比 + 进度条；**无上报时整区隐藏**，不占用空间
- 阶段切换时短暂高亮，暗示"进入新阶段"

### 3.4 间隔时间线——「节奏图」

**意图**：任务的"心电图"——回答*它现在节奏正常吗？哪一段卡住了？*

| 元素 | 内容 | 设计意图 |
|---|---|---|
| 累计时间线 | 整任务时间轴压缩为一条横带：每 chunk 一个色块（绿=快→红=慢），静默段留空 + 高亮边框 | 一眼看到任务全周期的快慢分布与静默段位置 |
| 最近间隔条 | 最近 60 个 chunk 的间隔柱状（保留现有热力条） | 细粒度观察当前节奏 |
| 交互 | 色块 hover 显示「距上一条 X.XXs」；静默段 hover 显示「静默 X 分钟」 | 数据可读而不是只有颜色暗示 |
| 关联（v1.0） | 点击时间线定位到对应终端输出（与回放联动） | 从节奏反查现场 |

### 3.5 终端窗口——「现场」

**意图**：完整真实的终端现场，是监控与干预的核心。
- 窗口标题栏：连接状态（实时/连接中/已断开/历史回放）+ 终端尺寸（cols×rows）+ 自动滚动开关 + 操作按钮组
- 主体 xterm.js：完整 ANSI/TUI 渲染、键盘输入、缩放自适应（resize 转发 PTY）
- 已结束任务：状态角标（「已成功 / 已终止」），终态不显示输入提示
- 空状态：未选中任务时显示 tmon 使用引导（见 3.6）

### 3.6 空状态与引导——「入口」

**意图**：第一印象与上手成本。
- 无任务时：居中展示 tmon 快速上手示例（代码块：`tmon "curl -o big.bin <url>"`）+ 简短说明 + 打开本仓库文档链接
- 有任务但未选中：轻提示「从左侧选择任务」

## 4. 状态视觉语义（统一规范）

| 状态 | 徽章 | 色条/点缀 | 动效 |
|---|---|---|---|
| running | 蓝底蓝字 | 蓝色 + 呼吸圆点 | 呼吸动画（live 感） |
| success | 绿底绿字 | 绿色 | — |
| failed | 红底红字 | 红色 | — |
| killed | 橙底橙字 | 橙色 | — |
| error（监控中断） | 灰底灰字 | 灰色 + 虚线 | — |

间隔热力渐变：`hsl(120 → 0)`（绿=快 → 红=慢），静默段用背景明暗 + 边框标注。

## 5. 样式系统

### 5.1 色彩（深色主题，VS Code 系）

| 用途 | 值 |
|---|---|
| 背景（侧边栏最深） | `#0a0e14` |
| 背景（主区） | `#0d1117` |
| 表面/卡片/窗口 | `#161b22` |
| 悬浮层 | `#1c2128` |
| 边框（弱/强） | `#21262d` / `#30363d` |
| 正文 | `#e6edf3` |
| 次级文字 | `#8b949e` |
| 强调（交互/链接） | `#58a6ff` |
| 成功 / 失败 / 终止 / 异常 | `#3fb950` / `#f85149` / `#d29922` / `#8b949e` |

**分层原则**：深色界面里不用阴影，用**背景明度递进 + 边框**制造层次（侧边栏最深 → 主区 → 卡片逐级变浅）。

### 5.2 字体

| 场景 | 字体 |
|---|---|
| 终端 / 命令 / 任务 id / 统计数字 | `Cascadia Code, Consolas, monospace` |
| UI 文本 | `Inter, "Segoe UI", "Microsoft YaHei", sans-serif` |

### 5.3 间距与圆角

- 间距基准 4px（4/8/12/16/24）
- 圆角：控件 6px，卡片 8px，徽章全圆
- 终端窗口：无内边距（终端渲染区紧贴边框，浏览器默认样式清干净）

### 5.4 交互细节

- 任务项 hover 浅层高亮；选中态强调色左条 + 背景
- 新任务进入列表：顶部滑入 + 短暂高亮（1.5s 渐隐）
- 状态翻转（running→结束）：任务项状态徽章一次脉冲
- 按钮：hover 边框提亮；危险按钮 hover 红色底 10%
- 复制成功：图标瞬时变为 ✓（1.5s 恢复）
- 侧边栏 running 任务时长每秒跳动（与详情统计同源 1s 定时器）

## 6. 组件树

```
App（选中任务状态 + hash 路由兼容 #/task/:id）
├── Sidebar
│   ├── Brand（logo + 版本 + server 状态点）
│   ├── TaskFilter（状态 tabs + 搜索框）
│   └── TaskList → TaskItem（状态色条 / id / 命令摘要 / 徽章 / 时长 / 微进度条）
└── Main
    ├── TaskHeader（身份 / 统计×4 / 操作组）
    ├── ProgressSection（条件渲染：阶段 + 百分比 + 进度条）
    ├── TimelineStrip（累计时间线 + 最近间隔条，hover 详情）
    └── TerminalPanel（标题栏 + xterm + 终态角标）
```

## 7. 响应式与边界

- 视口 ≥ 900px：左右分栏（侧边栏固定 300px，可拖拽调宽——v1.0）
- 视口 < 900px：侧边栏折叠为抽屉（汉堡按钮），主区占满
- 终端窗口最小高度 240px，flex 填充剩余空间
- 大量输出时：xterm 自带滚动 + 自动滚动开关（默认开）

## 8. 本次实现范围（本轮落地）

1. 左右分栏布局 + 侧边栏（筛选 / 搜索 / 任务项全套视觉）
2. 任务头（身份 + 统计 + 操作，含反馈）
3. 进度条区（条件渲染）
4. 间隔时间线（累计时间线 + 最近间隔条，hover 提示）
5. 终端窗口（标题栏 + xterm + 终态角标）
6. 空状态引导 + 响应式（<900px 抽屉）
7. hash 路由兼容（#/task/:id 直接打开对应任务并选中）

后续（v0.3+）：时间线点击定位输出、侧边栏宽度拖拽、键盘快捷键、通知角标。
